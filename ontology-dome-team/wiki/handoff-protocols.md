# 角色交接协议

角色之间的交接有标准格式，确保信息不丢、不模糊、不打太极。

## 总原则

1. **交接 = 任务包 + 产出物**，不是"你看着办"
2. **每个任务包必须写清**：输入是什么 / 输出要什么 / 验收标准是什么 / 约束是什么
3. **交接走 Orchestrator**，执行 Agent 之间不直接对接（避免私下改需求）
4. **PENDING 项必须随产物流转**，下游知道上游有哪些拿不准的

## Orchestrator → 业务调研 Agent

```markdown
## 环①② 任务包

### 任务编号：T-001
### 业务域：{domain 或 "待推导"}
### 输入
- 业务文档目录：{path}
- 文档格式：md / txt / pdf
- 文档数量：N 篇

### 输出
- 01_terms.md（术语对齐表）
- 02_scope.md（建模范围清单）
- 返回 JSON：{"terms": {...}, "scope": {"classes": [...], "relations": [...], "attrs": [...]}}

### 约束
- 够用原则：宁少勿滥
- 原文共现：每个术语/概念必须有原文依据
- 拿不准记 PENDING，不许硬套

### 验收标准（QA 会查）
- 每个术语有来源
- 消歧规则清晰
- 每个类有原文依据
- 不建清单有理由

### 优先级
- 主任务：术语提取 + 范围界定
- 次任务：PENDING 记录

### 截止（如果有）
- 时间盒：N 小时 / N 轮
```

## 业务调研 Agent → QA 验收官（经 Orchestrator 转发）

Orchestrator 转发时附：
- 产出物路径
- 环号：①②
- 验收级别：标准 / 加急

QA 返回：
- 验收报告（PASS / FAIL + 问题清单）
- 暗卷抽查结果（不公开具体用例，只说结果）

## QA 验收官 → Orchestrator

```markdown
## 环{X} 验收结果

### 结论：PASS / FAIL

### 问题清单
| 编号 | 严重度 | 描述 | 位置 |
|------|--------|------|------|
| P0-01 | 阻断 | ... | 文件:行号 |

### 暗卷结果
- 泛化测试：通过 / 未通过
- 边界测试：通过 / 未通过
- 反作弊检查：通过 / 未通过

### 建议
- 退回修改 / 降级处理 / 停止
```

## Orchestrator → 本体建模 Agent

```markdown
## 环③④ 任务包

### 任务编号：T-002
### 输入
- scope 数据：{JSON 或路径}
- 业务文档目录：{path}
- 上游 PENDING 项：{列表，注意这些是上游拿不准的}

### 输出
- 03_schema.json（本体 Schema）
- 04_instances.json（实例库）
- 返回 JSON：{"schema": {...}, "instances": {...}}

### 约束
- 命名规范：类 PascalCase / 属性 camelCase / 关系动词短语
- 中英映射：必须有 label_cn + description
- validate_ontology.py 必须 PASS
- 实例必须有来源标注

### 验收标准
- validate PASS
- 命名规范统一
- 中英映射完整
- 实例有来源

### 注意
- scope 有问题不要自己改，退回环②（通过我）
- 接口对不上立刻停，写 BLOCKED.md
```

## Orchestrator → 应用对接 Agent

```markdown
## 环⑤⑥ 任务包

### 任务编号：T-003
### 输入
- Schema：{JSON 或路径}
- 实例库：{JSON 或路径}
- 业务文档目录：{path}
- 上游 PENDING 项：{列表}

### 输出
- 05_rag.py（RAG 接入代码）
- 06_eval_report.md（评测报告）
- eval_result.json（结构化结果）
- 返回 JSON：{"eval_result": {...}}

### 约束
- 有本体/无本体双模式对比
- 评测集从实例库派生，不硬编码
- 串险种率必须是独立指标
- 评测数字必须可复现

### 验收标准
- RAG 代码可运行
- 评测数字可复现（重跑一致）
- 基线公平
- 串险种率真实
```

## Orchestrator → Engineer 工程手

```markdown
## 工程任务

### 任务类型：git 提交 / 依赖安装 / 环境配置 / ...
### 具体要求
- {详细描述}
- {路径 / 分支 / 版本信息}

### 约束
- 不改业务代码
- 不 force push 主分支
- 高风险操作先确认

### 期望输出
- 操作结果摘要
- 关键命令输出
- （如果有）下一步建议
```

## 异常交接：BLOCKED.md

任何角色遇到阻塞问题，立刻写 BLOCKED.md，格式：

```markdown
# BLOCKED · 阻塞问题清单

## B-001 · {问题标题}
- 严重度：P0 / P1 / P2
- 发现角色：{谁发现的}
- 状态：待裁决 / 处理中 / 已解决
- 描述：{具体问题}
- 证据：{命令输出 / 文件路径 / 截图描述}
- 影响：{阻塞了哪一环 / 什么任务}
- 建议处理方向：{你的建议，但不替领导拍板}
- 发现时间：{YYYY-MM-DD HH:MM}
```

写好后通知 Orchestrator，由 Orchestrator 判断是否需要上报 Human。
