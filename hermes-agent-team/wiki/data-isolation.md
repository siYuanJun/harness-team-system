# 四层数据隔离规范

## 概述

Hermes Agent Team 使用四层数据隔离机制，确保信息不会错放导致系统记忆污染。

## 四层定义

### Layer 1: Profile（角色定义）

**存放位置**：`.claude/agents/hermes-*.md`

**生命周期**：永久

**内容**：
- 角色定义（我是谁）
- 行为原则（我该做什么）
- 职责边界（我不做什么）
- 协作协议（如何与其他角色交互）

**特点**：
- 长期固定，不随项目变化
- 可跨项目复用
- 修改需要谨慎，影响所有使用该角色的项目

**示例**：
```markdown
---
name: hermes-researcher
description: "Hermes研究员。收集证据、标注置信度。"
---

# Researcher

你是 Hermes Agent Team 的研究员...

## 核心职责
1. 收集证据
2. 标注置信度
...
```

### Layer 2: Project（项目数据）

**存放位置**：`.ai-workflow/hermes/projects/{project-id}/`

**生命周期**：项目周期

**内容**：
- 任务目标
- 中间产出（研究报告、草稿）
- 最终交付物
- 审计报告
- 人类决策记录

**特点**：
- 与项目绑定，项目结束可归档
- 不包含通用知识
- 可追溯项目历史

**目录结构**：
```
.ai-workflow/hermes/projects/{project-id}/
├── 01_coordinator_tasks.md      # 任务拆解
├── 02_researcher_output.md      # 研究报告
├── 03_writer_draft.md           # 产出草稿
├── 04_editor_audit.md           # 审计报告
├── 05_human_decisions.md        # 人类决策
└── _workspace/                  # 中间文件
```

### Layer 3: Wiki（知识库）

**存放位置**：`hermes-agent-team/wiki/`

**生命周期**：永久

**内容**：
- 通用知识（架构规则、最佳实践）
- 跨项目共享的规范
- 工作流程定义
- 检查清单模板

**特点**：
- 跨项目共享
- 永久积累
- 不包含项目特定信息

**示例文件**：
- `architecture-rules.md` — 架构铁律
- `data-isolation.md` — 数据隔离规范
- `handoff-protocols.md` — 交接协议

### Layer 4: Session（会话数据）

**存放位置**：对话上下文

**生命周期**：会话周期

**内容**：
- 当前任务状态
- 临时数据
- 中间计算结果
- 对话历史

**特点**：
- 会话结束即失效
- 不持久化
- 不跨会话共享

## 数据流转规则

```
┌─────────────────────────────────────────────────────────────┐
│                      数据流转规则                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Wiki ──────→ Profile ──────→ Session                       │
│  (通用知识)    (角色定义)     (会话上下文)                    │
│     │              │              │                          │
│     │              │              ▼                          │
│     │              │         Project                         │
│     │              │         (项目数据)                      │
│     │              │                                         │
│     └──────────────┴───────────────────────────────         │
│                                                              │
│  规则:                                                       │
│  1. Wiki 可被所有层读取                                      │
│  2. Profile 可读取 Wiki                                      │
│  3. Session 可读取 Profile 和 Wiki                          │
│  4. Project 可读取所有层                                     │
│  5. Project 数据不可写入其他层                               │
│  6. Session 数据不可持久化                                   │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 常见错误

### 错误 1: 将项目数据写入 Wiki

**错误示例**：
```markdown
# Wiki: architecture-rules.md

## 项目特定规则
- 本项目使用 React 18
- 本项目使用 TypeScript
```

**正确做法**：
项目特定规则应写入 Project 层。

### 错误 2: 将通用知识写入 Project

**错误示例**：
```markdown
# Project: 01_coordinator_tasks.md

## 通用最佳实践
- 任务拆解应该遵循 SMART 原则
- 每个任务应该有明确的验收标准
```

**正确做法**：
通用知识应写入 Wiki 层。

### 错误 3: 在 Profile 中存储项目状态

**错误示例**：
```markdown
# Profile: researcher.md

## 当前任务
- 正在研究 AI Agent 协作模式
- 已完成 3 个来源的验证
```

**正确做法**：
当前任务状态应存储在 Session 或 Project 层。

## 检查清单

在写入数据前，检查：

- [ ] 数据属于哪一层？
- [ ] 写入位置是否正确？
- [ ] 是否会污染其他层？
- [ ] 是否符合数据流转规则？
