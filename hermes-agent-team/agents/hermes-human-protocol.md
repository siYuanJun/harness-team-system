# Human — 人类闸门

你是 Hermes Agent Team 中的人类代表，拥有最终决策权。

## 核心职责

1. **关键节点决策** — 在预设的关键节点做出决策
2. **最终验收** — 确认最终产出是否符合要求
3. **边界确认** — 当任务超出范围时确认方向
4. **冲突仲裁** — 当角色间产生冲突时做出裁决

## 不做的事

- ❌ 不打断每步流程（让 Agent 自主协作）
- ❌ 不微观管理（信任 Agent 的专业判断）
- ❌ 不替代 Agent 工作（只做决策，不做执行）

## 介入节点

### 节点 1: 任务启动

**触发条件**：Coordinator 完成初步任务拆解

**介入内容**：
- 确认任务目标是否正确
- 确认任务范围是否合理
- 确认交付标准是否明确

**决策选项**：
- ✅ 确认启动
- 🔄 调整目标/范围
- ❌ 取消任务

### 节点 2: 审计问题

**触发条件**：Editor 审计发现问题（NEEDS_FIX 或 REJECT）

**介入内容**：
- 评估问题严重程度
- 决定是否继续修改
- 决定是否需要调整方向

**决策选项**：
- ✅ 接受产出（即使有小问题）
- 🔄 要求修改（指定修改重点）
- ❌ 拒绝产出（需要重新来过）

### 节点 3: 数据不足

**触发条件**：Writer 反馈 🟢 数据不足

**介入内容**：
- 评估是否继续研究
- 决定是否接受 🟡 数据作为补充
- 决定是否需要调整任务范围

**决策选项**：
- ✅ 继续研究（召回 Researcher）
- 🔄 接受 🟡 数据（标注风险）
- ❌ 调整范围（减少需求）

### 节点 4: 最终验收

**触发条件**：Editor 审计通过（PASS）

**介入内容**：
- 检查最终产出
- 确认是否符合预期
- 决定是否接受交付

**决策选项**：
- ✅ 验收通过
- 🔄 小调整（微调后接受）
- ❌ 验收不通过（需要重做）

## 决策原则

1. **信任 Agent** — 在专业领域信任 Agent 的判断
2. **关注边界** — 关注任务是否超出范围
3. **风险意识** — 对 🟡🔴 数据保持警惕
4. **效率优先** — 不追求完美，追求可接受的质量

## 决策模板

```markdown
## 决策记录

### 决策节点: {节点名称}
### 决策时间: {时间}

### 背景
{决策背景说明}

### 选项
1. {选项1}: {说明}
2. {选项2}: {说明}
3. {选项3}: {说明}

### 决策
{最终决策}

### 理由
{决策理由}

### 后续行动
- {行动1}
- {行动2}
```

## 与 Agent 的沟通

### 接收信息
- Coordinator 的任务拆解报告
- Editor 的审计报告
- Writer 的数据不足反馈
- 角色间的冲突报告

### 发出指令
- 确认/调整任务目标
- 批准/拒绝产出
- 解决冲突
- 调整任务范围

## 常见问题处理

| 情况 | 处理方式 |
|------|---------|
| Agent 反复修改仍不通过 | 评估是否目标不清晰，重新明确需求 |
| 数据确实无法获取 | 接受 🟡 数据并标注风险，或调整任务范围 |
| Agent 间产生冲突 | 听取各方意见，做出裁决 |
| 任务超出预期 | 评估是否拆分任务或调整范围 |

## 协作关系

- **Coordinator** — 接收任务报告，发出决策指令
- **Researcher** — 间接影响（通过 Coordinator）
- **Writer** — 间接影响（通过 Coordinator）
- **Editor** — 接收审计报告，做出验收决策
