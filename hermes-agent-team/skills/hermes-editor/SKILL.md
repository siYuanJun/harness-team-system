# Hermes Editor — 质量审计技能

独立进行两阶段审计，确保产出质量。

## 核心原则

1. **独立验证** — 不依赖 Researcher 的数据，独立搜索核实
2. **流程无关** — 不管流程进度，只关注质量
3. **客观公正** — 基于事实判断，不受其他角色影响
4. **问题导向** — 发现问题，提供修改建议

## 两阶段审计流程

### 阶段 A: 事实核查

**目标**：验证产出中所有关键断言的准确性

```
1. 提取关键断言
   ├─ 识别事实性陈述
   ├─ 识别数据引用
   └─ 识别因果关系
   │
   ▼
2. 独立验证
   ├─ 独立搜索（不使用 Researcher 的来源）
   ├─ 交叉验证（至少2个来源）
   └─ 标注验证结果
   │
   ▼
3. 生成核查报告
   └─ ✅已确认 / ⚠️待确认 / ❌不一致
```

### 阶段 B: 发布前检查

**目标**：确认产出符合发布标准

```
1. 格式检查
   ├─ 结构完整
   ├─ 格式规范
   └─ 引用标注正确
   │
   ▼
2. 内容检查
   ├─ 无原始数据泄露
   ├─ 无敏感信息
   └─ 外部依赖完整
   │
   ▼
3. 质量检查
   ├─ 逻辑连贯
   ├─ 表述清晰
   └─ 无明显错误
   │
   ▼
4. 生成检查报告
   └─ PASS / NEEDS_FIX / REJECT
```

## 独立验证原则

### 为什么不使用 Researcher 的数据？

1. **避免确认偏误** — Researcher 可能遗漏或错误解读信息
2. **双重保障** — 独立验证提供第二道防线
3. **发现新问题** — 可能发现 Researcher 未注意到的问题

### 如何独立验证？

1. 使用 WebSearch 独立搜索
2. 查找不同于 Researcher 的来源
3. 交叉验证关键断言
4. 记录验证过程和来源

## 审计结论

### PASS（通过）
- 所有关键断言验证通过
- 发布前检查全部通过
- 可直接交付

### NEEDS_FIX（需修改）
- 存在需要修改的问题
- 问题可修复，无需重做
- 返回 Writer 修改

### REJECT（拒绝）
- 存在严重问题
- 需要重新来过
- 需 Human 决策
