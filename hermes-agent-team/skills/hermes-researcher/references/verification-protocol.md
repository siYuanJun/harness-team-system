# 来源验证协议

## 验证流程

```
1. 识别信息来源
   │
   ▼
2. 评估来源可靠性（A-E级）
   │
   ▼
3. 交叉验证（至少2个独立源）
   │
   ▼
4. 时效性检查
   │
   ▼
5. 最终置信度判定
```

## 来源可靠性分级

### A级 — 官方文档
- 官方网站（python.org, nodejs.org）
- 官方文档（docs.python.org）
- 官方 GitHub 仓库
- **可直接标🟢**

### B级 — 权威媒体
- 知名科技媒体（TechCrunch, The Verge, Ars Technica）
- 权威出版物（O'Reilly, Manning）
- 知名博客（个人但业界认可）
- **可直接标🟢**

### C级 — 社区验证
- Stack Overflow 高票答案（≥10票）
- GitHub Issues 中维护者的回复
- Reddit/HN 高票讨论
- **需交叉验证后可标🟢**

### D级 — 个人内容
- 个人博客文章
- Medium 文章
- 个人 GitHub 项目
- **只能标🟡**

### E级 — 未验证
- 社交媒体推文
- 论坛帖子
- 匿名来源
- **只能标🟡或🔴**

## 交叉验证方法

### 方法 1: 多源验证
同一事实在多个独立来源中得到确认。

**要求**：
- 至少 2 个独立来源
- 来源可靠性 ≥ B级
- 来源之间无转载关系

### 方法 2: 官方+社区验证
官方文档 + 社区实践验证。

**示例**：
- 官方文档说明某功能存在
- Stack Overflow 多个回答确认实际可用

### 方法 3: 实测验证
通过实际代码测试验证。

**适用**：技术细节、API 行为、性能数据

## 独立性判断

以下情况**不算**独立来源：
- 同一作者的不同文章
- 转载/引用同一原始来源
- 同一组织的不同账号
- AI 生成的多个回答

以下情况**算**独立来源：
- 不同组织的官方文档
- 不同作者的独立测试
- 官方文档 + 社区实测

## 时效性检查

| 信息类型 | 有效期 | 检查方法 |
|---------|--------|---------|
| 版本号/发布日期 | 永久 | 无需检查 |
| API 行为 | 2年 | 检查文档版本 |
| 性能数据 | 1年 | 检查测试环境 |
| 统计数据 | 1年 | 检查数据来源 |
| 最佳实践 | 3年 | 检查社区共识 |

## 验证记录模板

```markdown
### 验证记录: {断言}

**来源列表**:
1. [{来源名}]({URL}) — {可靠性等级}
2. [{来源名}]({URL}) — {可靠性等级}

**独立性检查**:
- [ ] 来源之间无转载关系
- [ ] 来源来自不同组织/作者
- [ ] 信息来源独立

**时效性检查**:
- [ ] 信息在有效期内
- [ ] 文档版本匹配
- [ ] 无过时警告

**最终判定**:
- 置信度: 🟢/🟡/🔴
- 理由: {判定理由}
```
