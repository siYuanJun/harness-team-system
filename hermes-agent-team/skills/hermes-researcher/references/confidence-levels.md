# 三级置信度标注规范

## 置信度定义

### 🟢 绿色（L1 - 已核实）

**定义**：多源验证、有直接证据

**标注条件**（必须全部满足）：
1. 至少 2 个独立来源确认
2. 来源可靠性 ≥ B级
3. 信息时效性在有效期内
4. 可直接引用

**示例**：
```markdown
🟢 Python 3.12 于 2023-10-02 发布
- 来源1: https://www.python.org/downloads/release/python-3120/
- 来源2: https://docs.python.org/3/whatsnew/3.12.html
- 验证: 两个独立官方来源一致
```

### 🟡 黄色（L2 - 估计值）

**定义**：单源或合理推断

**标注条件**（满足任一）：
1. 仅有 1 个来源
2. 来源可信但未完全验证
3. 基于已知信息的合理推断
4. 数据可能过时

**示例**：
```markdown
🟡 该框架用户量约 10 万+
- 来源: GitHub stars 约 12k（推断）
- 注意: 实际用户量可能更高
- 局限: 仅基于公开数据推断
```

### 🔴 红色（L3 - 推测）

**定义**：无直接证据、AI 生成

**标注条件**（满足任一）：
1. 无来源支持
2. 纯推测或假设
3. AI 生成的内容
4. 来源不可靠（E级）

**示例**：
```markdown
🔴 该团队可能使用 React 重写前端
- 无直接证据
- 基于招聘信息推测
- 禁止流入下游
```

## 标注规则

### 规则 1: 宁低不高
不确定时，选择更低的置信度级别。

### 规则 2: 来源必须记录
每条信息必须记录来源，即使是 🔴 也要说明为什么标红。

### 规则 3: 独立性要求
两个来源必须是独立的，不能是同一来源的转载。

### 规则 4: 时效性检查
技术信息需检查时效性，超过 2 年的信息需重新验证。

## 置信度流转规则

| 置信度 | 可流入下游 | 使用限制 |
|--------|-----------|---------|
| 🟢 绿色 | ✅ 可以 | 无限制 |
| 🟡 黄色 | ⚠️ 有条件 | 必须标注"估计值"，不可作为核心依据 |
| 🔴 红色 | ❌ 禁止 | 完全不可流入下游 |

## 特殊情况处理

### 来源冲突
当不同来源给出矛盾信息时：
1. 列出各方观点
2. 标注为 🟡（待确认）
3. 说明冲突原因
4. 请 Coordinator 决策

### 信息过时
当信息可能已过时时：
1. 标注原始日期
2. 评估时效性影响
3. 如影响核心结论，降级为 🟡
4. 建议 Researcher 更新

### 无法验证
当无法找到足够来源时：
1. 标注为 🔴
2. 说明已尝试的搜索方式
3. 建议替代研究方向
