# 常见问题排查

## 初始化阶段问题

### 问题 1: 无法确定执行模式

**症状**：不知道应该选择 Agent Teams、Sub-agents 还是混合模式

**排查步骤**：
1. 评估任务复杂度
2. 检查是否需要实时协作
3. 考虑成本预算

**解决方案**：
- 复杂任务 + 需要协作 → Agent Teams
- 简单任务 + 成本敏感 → Sub-agents
- 阶段性任务 → 混合模式

### 问题 2: 角色职责重叠

**症状**：多个角色职责不清，产生冲突

**排查步骤**：
1. 检查每个角色的核心职责
2. 确认职责边界
3. 验证协作协议

**解决方案**：
- 明确每个角色的"做"与"不做"
- 遵循"管流程的不管质量"原则
- 使用交接协议明确责任

### 问题 3: 项目规模评估错误

**症状**：配置过于复杂或过于简单

**排查步骤**：
1. 统计预计任务数量
2. 评估任务复杂度
3. 考虑未来扩展需求

**解决方案**：
- 小型项目（<10任务）：简化配置，使用 Sub-agents
- 中型项目（10-20任务）：标准配置，Agent Teams
- 大型项目（>20任务）：完整配置，混合模式

## 运行阶段问题

### 问题 4: Researcher 返回数据不足

**症状**：🟢 绿色数据不足，Writer 无法继续

**排查步骤**：
1. 检查研究范围是否明确
2. 验证搜索策略是否正确
3. 评估来源可靠性标准

**解决方案**：
- 明确研究范围和关键词
- 调整搜索策略，扩大搜索范围
- 适当降低来源可靠性要求（但仍需标注）
- 召回 Researcher 补充研究

### 问题 5: Editor 审计发现问题

**症状**：Editor 返回 NEEDS_FIX 或 REJECT

**排查步骤**：
1. 查看审计报告中的具体问题
2. 分析问题类型（事实错误/格式问题/质量问题）
3. 确定修改方案

**解决方案**：
- 事实错误：返回 Writer 修改，必要时召回 Researcher
- 格式问题：Writer 直接修改
- 质量问题：评估是否可接受，或需要重做
- 最多 3 轮修改，超过需 Human 决策

### 问题 6: Agent 间通信失败

**症状**：消息未送达或信息丢失

**排查步骤**：
1. 检查通信协议配置
2. 验证文件路径是否正确
3. 确认消息格式是否一致

**解决方案**：
- 使用标准化的交接协议
- 使用绝对路径而非相对路径
- 在消息中包含必要的上下文
- 重要信息通过文件传递，不依赖会话

### 问题 7: 任务依赖循环

**症状**：任务 A 依赖任务 B，任务 B 又依赖任务 A

**排查步骤**：
1. 绘制任务依赖图
2. 检查是否有循环依赖
3. 分析任务拆解是否合理

**解决方案**：
- 重新拆解任务，消除循环依赖
- 引入中间任务打破循环
- 调整任务执行顺序

## 质量保障问题

### 问题 8: 置信度标注不准确

**症状**：🟢🟡🔴 标注与实际可靠性不符

**排查步骤**：
1. 检查来源可靠性分级
2. 验证交叉验证是否执行
3. 评估标注标准是否一致

**解决方案**：
- 严格执行来源可靠性分级（A-E级）
- 确保至少 2 个独立来源才能标🟢
- 统一标注标准，避免主观判断
- 定期审核标注质量

### 问题 9: Editor 独立性不足

**症状**：Editor 直接使用 Researcher 的数据，未独立验证

**排查步骤**：
1. 检查 Editor 的验证流程
2. 验证是否使用 WebSearch 独立搜索
3. 确认是否记录验证过程

**解决方案**：
- 强调 Editor 独立性原则
- 要求 Editor 独立搜索验证
- 记录验证过程和来源
- 审核 Editor 的审计报告质量

### 问题 10: 人类闸门介入过多

**症状**：Human 被频繁打扰，影响效率

**排查步骤**：
1. 检查介入节点设置
2. 评估决策类型是否都需要 Human
3. 分析是否可以自动化部分决策

**解决方案**：
- 只在关键节点介入（启动/审计问题/数据不足/验收）
- 明确决策权限，部分决策可自动化
- 优化交接协议，减少不必要的确认

## 性能优化问题

### 问题 11: 执行速度过慢

**症状**：任务完成时间过长

**排查步骤**：
1. 分析各阶段耗时
2. 检查是否有瓶颈
3. 评估是否可以并行化

**解决方案**：
- 使用 Fan-out/Fan-in 模式并行研究
- 优化任务拆解，减少依赖
- 适当简化流程（如跳过不必要的审计）
- 使用 Sub-agents 替代 Agent Teams（减少通信开销）

### 问题 12: 成本过高

**症状**：Token 消耗过大，成本超出预算

**排查步骤**：
1. 分析各角色的 Token 消耗
2. 检查是否有冗余操作
3. 评估执行模式是否合适

**解决方案**：
- 使用 Sub-agents 替代 Agent Teams
- 减少 Researcher 并行数量
- 简化审计流程
- 优化提示词，减少 Token 消耗

## 集成问题

### 问题 13: 与现有 Skill 冲突

**症状**：触发 Hermes 时触发了其他 Skill

**排查步骤**：
1. 检查 description 是否与其他 Skill 重叠
2. 验证触发词是否独特
3. 分析 Skill 优先级

**解决方案**：
- 调整 description，明确边界
- 使用更独特的触发词
- 在 description 中明确排除场景

### 问题 14: CLAUDE.md 配置不生效

**症状**：CLAUDE.md 中的触发规则未生效

**排查步骤**：
1. 检查 CLAUDE.md 格式是否正确
2. 验证触发规则是否清晰
3. 确认 Skill 是否正确安装

**解决方案**：
- 按照模板格式配置 CLAUDE.md
- 明确触发条件和关键词
- 重新安装 Skill，确保文件完整
