# Ontology-Brain Team · 本体工程师数字员工团队

## 触发场景

当用户说以下内容时触发本 Harness 团队：

- "跑一下本体建模流水线"
- "开始六环"
- "对这个文档做本体分析"
- "生成术语表和 Schema"
- "本体工程师数字员工"
- "ontology-brain 团队"

---

## 定位与适用范围（重要 · 用前必读）

**本团队是垂直团队，不是通用团队。用错领域会导致角色职责和产出物完全不匹配。**

### 适用场景

- 本体建模 / 知识图谱构建
- 业务文档 → 术语表 / Schema / 实例库 / RAG 代码 的六环流水线
- 本体工程师数字员工相关任务
- 任何需要本体工程能力的项目

### 不适用场景（请勿使用本团队）

- 通用软件开发（前端 / 后端 / 移动端 / 全栈）
- 数据分析 / 报表 / 可视化
- 爬虫 / 自动化运维
- 内容创作 / 文案 / 翻译
- 任何非本体工程领域的任务

### 为什么是垂直的（不可直接复用的部分）

| 绑定项 | 说明 |
|--------|------|
| 角色前缀 | `brain-*`（brain-pm、brain-modeling-agent 等），本示例团队的统一前缀 |
| 核心流水线 | 本体工程六环：术语提取→概念识别→Schema设计→实例灌入→RAG接入→对比评测 |
| 产出物 | 术语表 / 范围清单 / Schema.json / 实例库 / RAG代码 / 评测报告（本体工程特定） |
| 质量门标准 | 泛化能力 / Schema validate PASS / RAG数字可复现（本体工程特定） |

### 如果要用于其他项目，必须改造

1. **角色前缀**：`brain-*` → 项目前缀（如 `ecom-*`、`spider-*`）
2. **流水线**：六环 → 该项目的实际流程（如需求→设计→开发→测试→部署）
3. **产出物**：本体工程产物 → 该项目的实际产物
4. **质量门标准**：本体工程标准 → 该项目的验收标准
5. **可保留**：7 角色架构、管流程不管质量铁律、3 质量门机制、明卷+暗卷+反作弊验收方法

### 通用方法论在哪里

团队搭建的通用方法论：`harness/_methodology/team-building-methodology.md`

本团队（ontology-brain-team）是该通用方法论的**一个垂直落地实例**，不是方法论本身。

## 六环流水线

```
环① 术语提取 ─┐
              ├─→ 业务调研 Agent → QA 验收 → 质量门一
环② 概念识别 ─┘

环③ Schema 设计 ─┐
                 ├─→ 本体建模 Agent → QA 验收 → 质量门二
环④ 实例灌入    ─┘

环⑤ RAG 接入 ─┐
              ├─→ 应用对接 Agent → QA 验收 → 质量门三
环⑥ 对比评测 ─┘
```

每环产物 → QA 独立验收 → PASS 才进下一环。

## 质量门

三道质量门，明卷 + 暗卷 + 反作弊三层检查：

| 质量门 | 检查对象 | 重点 |
|--------|---------|------|
| 门一（环①②→③） | 术语表 + 范围清单 | 泛化能力 / 消歧有效性 / 够用原则 |
| 门二（环③④→⑤） | Schema + 实例库 | validate PASS / 命名规范 / 来源标注 |
| 门三（环⑤⑥→交付） | RAG 代码 + 评测报告 | 数字可复现 / 基线公平 / 反作弊 |
