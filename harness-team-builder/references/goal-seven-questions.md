# 目标七问法（khazix leader 心法蒸馏）

> 来源：khazix-skills 的 leader Skill。蒸馏其核心心法，用于团队搭建前的需求澄清。

## 第零问：这张海图是你自己测的，还是听来的

动笔前一定先钻进代码库亲手跑一遍——读 README / CLAUDE.md / 代码结构 / git 状态 / 依赖可行性。文档里写的命令，实际可能根本不存在。不要照抄文档，要实测。

## 七问

| # | 问题 | 出海版类比 | 落到团队搭建 |
|---|------|-----------|-------------|
| 1 | **目的** | 我们为什么出这趟海，找香料还是探航线 | 这个项目为什么需要团队？解决什么核心问题？遇到没写到的岔路口，团队靠这句自己判断 |
| 2 | **完成态** | 「出去转一圈」不算，「带回三船香料」才算 | 团队搭好后，什么状态算完成？具体到机器能判：`.claude/agents/` 有 N 个文件、路由表可触发、git 已提交 |
| 3 | **证据** | 谁上船清点货舱。不能船长说满载就是满载 | 每条验收都要贴出实际命令输出。不能说"团队可用"，要说"触发词 X 路由到角色 Y，执行了命令 Z，输出是 W" |
| 4 | **反作弊** | 不许劫商船凑数：指标达成，事一件没干 | 把偷懒路径一条条点名禁止。比如：不允许角色文件只有标题没有职责；不允许路由表写了但角色不存在；不允许跳过实测直接说"配置完成" |
| 5 | **地界** | 只许走这三条航线；粮食只够三十天 | 白名单：只许动 `.claude/` 目录和 `CLAUDE.md`，不许改业务代码；跑满 N 轮即停 |
| 6 | **取舍** | 风暴里保货还是保船？不说，船长只能猜 | 团队搭建的优先级：角色职责清晰 > 角色数量多 > 文档好看。冲突时按这个排序 |
| 7 | **未知** | 空白海域别硬闯也别抛锚，记下来绕过去 | 拿不准的（比如项目是否需要 Worktree 并行）写进待裁决清单，先搭基础团队，后续再扩展 |

## 使用方式

团队搭建前，先按七问输出一份需求澄清，和用户确认后再动手。七问的答案直接影响：
- 团队规模选型（目的和完成态决定需要多少角色）
- 架构模式选型（任务特性决定流水线还是扇出扇入）
- 角色选择（地界和取舍决定哪些角色必备）
- 验收标准（证据和反作弊决定怎么验）

## 核心原则

- Goal 告诉 AI 往哪走，Harness 告诉它哪些路不许走。**没有 Harness 的 Goal，AI 永远会找到你没想到的捷径。**
- 目标里最重要的部分，是「什么不能做」。
- 多出来的约束（如"安全返回"），一笔删掉了最省力的错误解法。
