# 对话日志协议（Dialogue Log Protocol）

评审全过程必须留痕。对话日志是评审的"庭审记录"：**谁说了什么、确定了什么、理解了什么、定性了什么**，全部可追溯。

## 日志文件

- 位置：`.prd-reviews/{日期}-{文档名}/10-dialogue-log.md`
- 写入方式：**追加式**（append-only），按时间顺序，禁止事后改写已有条目
- 写入责任人：**编排者**（各阶段结束后立即追加，不等流程跑完再补记）

## 四类日志条目

| 类型 | 标记 | 含义 | 典型来源 |
|------|------|------|----------|
| 陈述 | 🗣️ SAY | 谁说了什么：观点、质疑、回应、理由 | 独立评审结论、辩论发言 |
| 确定 | ✅ DECIDE | 确定了什么：达成的结论、裁决结果 | 共识条目、技术经理裁决、分歧仲裁 |
| 理解 | 🧠 UNDERSTAND | 理解了什么：团队对 PRD 的共同理解 | 行业定位、事实前提、对 PRD 意图的解读 |
| 定性 | 🏷️ LABEL | 定性了什么：对事物的性质判断 | 真/伪痛点、高/低价值、夸大表述、复杂度级别 |

## 条目格式

```markdown
| # | 时间 | 阶段 | 发言人 | 类型 | 内容 | 引用 |
|---|------|------|--------|------|------|------|
```

字段说明：
- **#**：全局递增编号（L1, L2, …），跨阶段连续
- **时间**：写入时刻（HH:MM 即可）
- **阶段**：P0 准备 / P1 独立评审 / P2 辩论轮1 / P2 辩论轮2 / P3 共识 / P4 裁决 / P5 交付
- **发言人**：PM1 / PM2 / PM3 / 技术经理 / 编排者（系统事实由编排者记录）
- **类型**：🗣️ SAY / ✅ DECIDE / 🧠 UNDERSTAND / 🏷️ LABEL
- **内容**：一句话摘要，保留发言人原意的关键措辞；长内容用"详见 {文件}"指向过程文件
- **引用**：关联的条目编号（I1/V2/R3…）或过程文件名，可为空

## 各阶段写入要求

| 阶段 | 必须记录的条目 |
|------|----------------|
| P0 准备 | 🧠 团队对 PRD 的初始理解（文档主题、章节结构、评审范围） |
| P1 独立评审 | 每位 PM 的 🗣️ 核心结论（各 1-3 条）+ 🏷️ 所有定性判断（痛点分级、价值评级、夸大标记等，逐条） |
| P2 辩论轮1 | 每条质疑的 🗣️（质疑方+理由）与被质疑方的 🗣️ 回应（坚持/让步/部分接受）；让步导致的 🔄 结论修订记为新 🗣️ 条目并注明推翻的旧条目 |
| P2 辩论轮2 | 每位 PM 的最终立场（对关键条目各 1 条 🗣️） |
| P3 共识 | 每条共识 1 条 ✅ DECIDE（含通过比例）；分歧项 🗣️ 记录双方立场；新形成的共同理解记 🧠 |
| P4 裁决 | 每条裁决 1 条 ✅ DECIDE（裁决类型+理由摘要）；被否决项附替代方案；技术补充 🏷️ 定性 |
| P5 交付 | ✅ 记录最终交付物清单与评审结论 |

## 评审范围确认

## 铁律

1. **先记录后流转** — 每阶段产出落盘后，日志追加完成才进入下一阶段
2. **定性必须有出处** — 🏷️ 条目的"引用"列必须指向评审产出中的具体位置
3. **不合并、不改写** — 同一人前后立场变化记两条（体现过程），禁止覆盖旧条目
4. **日志不是复述** — 摘要到"看日志能还原决策链"即可，全文细节去过程文件查
